## 1. ZIP 만들기

빌드 시 API 주소를 파일 안에 구워 넣어야 하므로, **환경변수 `CHEVROLET_API_BASE_URL`을 먼저 지정**한다.

### PowerShell(권장, 현재 환경)
```powershell
$env:CHEVROLET_API_BASE_URL = 'https://chevrolet-api-813801981857.asia-northeast3.run.app'

# 프론트
cd C:\Users\hanwonchae\Desktop\CHEVROLETcode\front-plugin
.\package.ps1        # -> chevrolet-front-plugin.zip

# POS (내부에서 npm run build까지 실행)
cd C:\Users\hanwonchae\Desktop\CHEVROLETcode\pos-plugin
.\package.ps1        # -> chevrolet-pos-plugin.zip (루트 구조) + chevrolet-pos-plugin-foldered.zip (dist/ 구조)
```

> POS `package.ps1`은 **두 가지**를 만든다: 루트 구조와 `-foldered`(dist/) 구조.
> 개발자센터에는 **`-foldered`를 올린다.**

### 올바른 ZIP인지 검증 (중요)
업로드 전에 아래 두 가지를 확인한다.
1. **경로 구분자가 슬래시(`/`)** 여야 한다. 백슬래시(`\`)면 토스가 거부한다.
2. **API 주소가 실제로 주입**됐는지(`__CHEVROLET_API_BASE_URL__` 자리표시자가 남아있으면 안 됨).

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z = 'C:\Users\hanwonchae\Desktop\CHEVROLETcode\pos-plugin\chevrolet-pos-plugin-foldered.zip'
$zip = [System.IO.Compression.ZipFile]::OpenRead($z)
$zip.Entries | ForEach-Object { $_.FullName }   # dist/bundle.js 처럼 슬래시여야 정상
$zip.Dispose()
```

## 2. ⚠️ 겪은 함정 — 왜 POS가 처음에 안 올라갔나

**증상:** POS ZIP을 올리면 개발자센터가 거부. 프론트는 정상.

**원인 2가지가 겹쳤다:**
1. **백슬래시 구분자.** Windows의 `Compress-Archive`와 .NET `ZipFile.CreateFromDirectory`는
   ZIP 내부 경로를 백슬래시(`dist\bundle.js`)로 쓴다. ZIP 표준은 슬래시(`/`)라 토스가 거부한다.
   프론트는 하위 폴더가 없어(파일이 전부 최상위) 구분자가 아예 안 생겨서 우연히 통과했다.
2. **폴더 래핑 필요.** POS는 산출물을 `dist/`로 감싼 구조를 요구한다(루트에 흩뿌리면 거부).

**해결:** Windows 내장 `tar.exe`(libarchive)는 슬래시로 zip을 만든다. 수동으로 다시 만들 때:
```bash
# Git Bash. /usr/bin/tar(GNU)가 아니라 Windows tar.exe를 써야 한다(GNU tar는 .zip을 못 만든다).
WT="/c/Windows/System32/tar.exe"

# POS: dist 폴더째 감싸기
cd /c/Users/hanwonchae/Desktop/CHEVROLETcode/pos-plugin
"$WT" -a -cf chevrolet-pos-plugin-foldered.zip dist

# 검증: 첫 2바이트가 PK 여야 진짜 zip
head -c 2 chevrolet-pos-plugin-foldered.zip   # -> PK
```

> `pos-plugin/package.ps1`은 이 문제를 자동으로 처리해 `-foldered` zip을 슬래시로 만들어 둔다.
> 스크립트를 쓰면 위 수동 작업은 필요 없다.

## 3. 개발자센터 업로드

1. https://developers.tossplace.com/login (사업자 계정 필요 — 대행 불가)
2. **내 플러그인 → 플러그인 등록**. 프론트는 `토스프론트`, POS는 `토스 POS` 타입.
3. **ACL**에 운영 API 주소 등록:
   `https://chevrolet-api-813801981857.asia-northeast3.run.app`
   (프론트/POS **양쪽 플러그인 모두**. 기존 Render 주소가 등록돼 있어도 전환 확인 전까지 지우지 말 것)

5. 개발 트랙(테스트 단말기)에서 먼저 확인한 뒤 운영 전환.

## 4. 서버(Cloud Run) 운영 체크리스트

### 4.1 환경변수 / 시크릿
Cloud Run → `chevrolet-api` → **새 버전 수정 및 배포** → **변수 및 보안 비밀** → 저장 → 배포.

| 이름 | 값 | 비고 |
|---|---|---|
| `TOSS_WEBHOOK_SECRET` | 개발자센터 웹훅에 넣은 값과 **동일** | 🔴 없으면 서버가 부팅 거부. Secret Manager로 관리 중이면 새 버전 올린 뒤 버전이 `latest`인지 확인하고 재배포 |
| `ADMIN_ALLOWED_ORIGINS` | `https://chevrolet-api-813801981857.asia-northeast3.run.app` | 관리자 API 허용 오리진 |
| `DATA_RETENTION_DAYS` | `1095` | 개인정보 보관기간 |
| `PROMO_MAX_PER_RUN` | `2000` | 프로모션 1회 최대 발송 |
| `DATABASE_URL` | 기존 값 끝에 `&connection_limit=5` | 🟡 인스턴스 20개 × 풀 → Cloud SQL 커넥션 한도 초과 방지. `?`가 이미 있으면 `&`로, 없으면 `?`로 시작해야 함 |

> ⚠️ 시크릿을 `보안 비밀`에 등록해두면 같은 이름을 `환경 변수`로 또 만들 수 없다("이름은 고유해야
> 합니다" 에러). 이미 등록돼 있으면 값만 새 버전으로 갱신하면 된다.

### 4.2 웹훅 등록 + 검증
- 개발자센터 → 내 애플리케이션 → **OpenAPI → 웹훅**:
  - 수신 URL: `https://chevrolet-api-813801981857.asia-northeast3.run.app/api/webhooks/toss/payment`
  - 서명 secret: `TOSS_WEBHOOK_SECRET`과 **동일한 값**
  - ⚠️ 이 값은 "토스페이먼츠 시크릿 키"(live_sk_…)가 아니다. 우리가 정하는 임의의 랜덤 문자열이다.
- 검증(키를 채팅/로그에 노출하지 말 것):
  ```powershell
  cd C:\Users\hanwonchae\Desktop\CHEVROLETcode
  $env:TOSS_WEBHOOK_SECRET = '실제키'
  $env:WEBHOOK_TARGET = 'https://chevrolet-api-813801981857.asia-northeast3.run.app/api/webhooks/toss/payment'
  node backend\scripts\verify-webhook.js
  # ✅ ①200 ②401 ③400 이면 통과
  ```

### 4.3 Cloud Scheduler 잡 2개 (안 하면 프로모션·개인정보 파기가 영영 안 돎)
서버 안에는 스케줄러가 없다. Cloud Scheduler가 아래 endpoint를 주기 호출해야 동작한다.
- ⚠️ **먼저 기존 잡 확인**: 2026-08-05 구성 때 `chevrolet-promotion-daily`가 이미 등록됐을 수 있다.
  ```bash
  gcloud scheduler jobs describe chevrolet-promotion-daily --location=asia-northeast3 --project=tossplugincar-dev
  ```
  있으면 새로 만들지 말고 헤더 토큰만 `update`한다(중복 호출 방지).
- 없을 때 등록:
  ```bash
  gcloud scheduler jobs create http chevrolet-send-promotions \
    --project=tossplugincar-dev --location=asia-northeast3 \
    --schedule="0 10 * * *" --time-zone="Asia/Seoul" \
    --uri="https://chevrolet-api-813801981857.asia-northeast3.run.app/internal/jobs/send-promotions" \
    --http-method=POST --headers="X-Promotion-Job-Token=<PROMOTION_JOB_TOKEN 실제 값>"

  gcloud scheduler jobs create http chevrolet-purge-expired \
    --project=tossplugincar-dev --location=asia-northeast3 \
    --schedule="0 4 * * *" --time-zone="Asia/Seoul" \
    --uri="https://chevrolet-api-813801981857.asia-northeast3.run.app/internal/jobs/purge-expired" \
    --http-method=POST --headers="X-Promotion-Job-Token=<PROMOTION_JOB_TOKEN 실제 값>"
  ```
  재시도가 있어도 서버가 claim/promoSent·anonymizedAt으로 중복을 막으므로 안전하다.

### 4.4 매장별 POS 토큰 발급 (안 하면 POS 대기열이 안 뜸)
- 관리자 화면(`/admin.html`) 로그인 → **매장 관리 → POS 토큰**.
- 매장마다 **직접 지정**(4자 이상, 예: `gn01`)하거나 **무작위 재발급**. 그 값을 POS 태블릿에 한 번 입력.
- 토큰이 틀린 시도는 15분 10회로 제한되므로 짧아도 무차별 대입은 막힌다. 유출되면 재발급 한 번으로 무효화.

## 5. 코드 배포(자동)

`main`에 push하면 Cloud Build 트리거가 Docker 이미지를 빌드해 Cloud Run에 자동 배포한다.
- 빌드 상태: https://console.cloud.google.com/cloud-build/builds?project=tossplugincar-dev
- 새 코드 반영 확인: `/health/ready`가 `200 {"ok":true}` 인지.
- ⚠️ Cloud SQL이 꺼져 있으면 부팅 시드 단계에서 실패해 모든 리비전이 크래시한다. 배포 전 Cloud SQL이
  떠 있는지 확인하고, 가능하면 **자동 중지를 꺼둘 것**.
