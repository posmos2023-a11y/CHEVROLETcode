# 쉐보레 정비 전산 (연동 시뮬레이터)

정비소 ERP를 흉내낸 PyQt5 데스크톱 앱입니다. 정비소 직원이 부품·소모품·공임을
장바구니에 담고 **[POS로 전송]** 버튼을 누르면 백엔드 API(`/api/erp/carts`)로
장바구니를 전송합니다. 이후 토스 POS 안의 플러그인이 그 장바구니를 받아가서
POS 장바구니에 담고 결제 화면을 띄우는 흐름을 MOU 시연 및 연동 검증용으로
재현하기 위한 도구입니다.

이 앱 자체는 API 호출까지만 담당합니다. POS 쪽 플러그인은 별도로 개발 중입니다.

## 화면 구성

- **상단 바**: 앱 제목, 매장코드, [설정] 버튼
- **좌측 (품목 선택)**: 차량번호/고객명 입력, 카테고리 탭(전체/부품/소모품/공임),
  품목 검색, 품목 목록 (더블클릭 또는 [담기] 버튼으로 장바구니에 추가)
- **우측 (장바구니)**: 담긴 품목 목록(수량 ± 조절, 삭제), 공급가/부가세/합계,
  "결제까지 자동 진행" 체크박스, [비우기] / [POS로 전송] 버튼
- **하단 상태줄**: 마지막 전송 결과. 전송 후 2초 간격(최대 60초)으로 상태를
  폴링해 대기중(노랑) → 성공(초록) / 실패(빨강)로 갱신됩니다. 대기 중에는
  [취소] 버튼으로 서버 측 장바구니를 취소할 수 있습니다.

### [장바구니 복원] 버튼

전송에 성공하면 다음 손님을 받을 수 있게 장바구니를 곧바로 비웁니다. 그런데 POS 쪽에서
담기가 실패하면 그 건은 서버에서 끝난 상태(`failed`)라 **전산이 다시 보내야** 하는데,
장바구니가 이미 비어 있으면 품목을 처음부터 다시 골라야 합니다. 부품 여러 개에 공임까지
섞인 정비 주문에서는 손해가 커서, 보낸 내용을 그대로 들고 있다가 되살릴 수 있게 했습니다.

- **담기 실패**로 끝나면 버튼이 뜹니다. 누르면 품목·수량·차량번호·고객명이 그대로 복구됩니다.
- **60초 응답 없음**일 때도 뜨지만, 이 경우는 POS가 나중에 담아갈 수도 있어서 누르면
  "같은 주문이 두 번 담길 수 있다"는 확인을 한 번 받습니다.
- **정상적으로 담긴 경우에는 뜨지 않습니다** — 같은 주문을 두 번 보내는 사고를 막기 위해서입니다.
- 이미 다음 손님 품목을 담기 시작했다면 버튼이 뜨지 않습니다(두 손님 것이 섞이는 사고 방지).

## 설치 및 실행 (PowerShell)

```powershell
cd erp-simulator
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

`python`이 없다면 먼저 `python --version`으로 설치 여부를 확인하고,
[python.org](https://www.python.org/downloads/)에서 3.9 이상을 설치하세요.

## 단독 실행파일(.exe)로 묶기

시연은 파이썬이 없는 PC에서 하는 경우가 많습니다. exe 하나만 복사하면 바로 뜹니다.

```powershell
python -m pip install pyinstaller
cd erp-simulator
.\build.ps1
```

산출물: `dist\쉐보레정비전산.exe` (약 33MB, 단일 파일)

- `-Clean` 옵션을 주면 이전 산출물까지 지우고 새로 빌드합니다.
- **`config.ini`는 exe에 들어가지 않습니다.** ERP 토큰이 담기는 파일이라 구워넣으면 그 exe를
  받는 사람 모두에게 토큰이 새어나갑니다. 대신 처음 실행할 때 **exe 옆에** 새로 만들어지고,
  [설정]에서 넣은 토큰은 거기 저장됩니다. 그래서 **exe를 남에게 줄 때는 exe 파일만** 주세요
  (같은 폴더의 `config.ini`를 함께 주면 토큰이 그대로 넘어갑니다).
- `style.qss`와 `config.example.ini`는 읽기 전용 리소스라 exe 안에 함께 들어갑니다.
- `dist/`, `build/`, `*.spec`은 `.gitignore`에 등록돼 있습니다.

## 설정

앱을 처음 실행하면 `config.example.ini`를 복사해 `config.ini`가 자동으로
생성됩니다. 아래 세 값을 채워야 전송이 동작합니다.

```ini
[api]
base_url = https://chevrolet-api-813801981857.asia-northeast3.run.app
erp_token =
store_code = CHV-001
```

- **`erp_token`은 백엔드 운영자(서버 쪽 `ERP_API_TOKEN` 환경변수를 발급한 사람)에게
  요청해서 받으세요.** 이 값이 없으면 서버가 모든 `/api/erp/*` 요청을 401로
  거부합니다.
- 앱 우측 상단 **[설정]** 버튼을 눌러도 같은 값을 GUI에서 편집할 수 있습니다.
  ERP 토큰 입력란은 화면을 몰래 보는 사람이 있을 수 있는 카운터 환경을
  고려해 비밀번호 방식(●●●)으로 가려집니다.
- 환경변수 `CHEVROLET_API_BASE_URL`, `CHEVROLET_ERP_TOKEN`, `CHEVROLET_STORE_CODE`가
  설정되어 있으면 `config.ini`보다 **우선** 적용됩니다. CI/데모 서버처럼
  파일을 남기고 싶지 않은 환경에서 씁니다.

### 절대 커밋하지 마세요

`config.ini`에는 ERP 토큰(비밀값)이 그대로 저장됩니다. 저장소 루트
`.gitignore`에 `erp-simulator/config.ini`를 이미 등록해뒀지만, 강제로
`git add -f` 등으로 추가하지 않도록 주의하세요. 커밋해도 되는 건 토큰 칸이
비어 있는 `config.example.ini`뿐입니다.

## API 없이도 동작합니다

`/api/erp/carts` 계열 API는 아직 배포 전일 수 있습니다. 이 앱은 네트워크
호출을 전부 백그라운드 스레드에서 처리하고 실패를 화면에 한국어 메시지로
보여주도록 만들어져 있어서, API가 없어도 담기/수량 변경/삭제/합계 계산 등
장바구니 UI 전체가 정상 동작합니다. [POS로 전송]을 눌렀을 때만 연결 실패
메시지가 상태줄에 표시됩니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `main.py` | 진입점 + 메인 윈도우(화면 전체) |
| `catalog.py` | 정비소 품목 목데이터 |
| `cart.py` | 장바구니 모델 (합계/부가세 계산) |
| `api.py` | HTTP 클라이언트 + QThread 워커(전송/폴링/취소) |
| `config.py` | 설정 로드/저장 (환경변수 우선순위 포함) |
| `style.qss` | 스타일시트 |
| `config.example.ini` | 설정 템플릿 (커밋 대상) |
| `config.ini` | 실제 설정 (커밋 금지, `.gitignore` 처리됨) |

## 개발 메모

- 부가세는 부가세 포함가 기준 역산으로 계산합니다: `tax = round(total / 11)`,
  `supply = total - tax`. 서버가 검증하는 `totalAmount`는 항상
  `Σ(unitPrice × quantity)`와 정확히 일치합니다 (정수 원 단위 곱셈/합이라
  부동소수점 오차가 생기지 않습니다).
- `referenceId`는 전송할 때마다 `ERP-YYYYMMDD-HHMMSS-<3자리 난수>` 형식으로
  새로 생성됩니다 (멱등키이므로 같은 값을 재사용하면 서버가 중복 처리합니다).
- 네트워크 호출(전송/상태조회/취소)은 전부 `QThread` 워커에서 실행되고
  결과는 Qt 시그널로만 메인 스레드에 전달됩니다. UI가 멈추는 일이 없도록
  하기 위함입니다.
