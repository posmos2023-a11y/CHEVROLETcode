■ ERP 토큰 (X-ERP-Token) — 전산이 우리 서버를 부를 때 쓰는 값

  Cloud Run → chevrolet-api → [리비전] 탭 → 맨 위(최신) 리비전 클릭
            → 오른쪽 패널 [변수] 탭 → ERP_API_TOKEN

  https://console.cloud.google.com/run/detail/asia-northeast3/chevrolet-api/revisions?project=tossplugincar-dev

  * 평문 환경변수라 이 화면에서 바로 보입니다(읽기 전용이라 안전).
  * 이 값을 PyQt 전산 앱 [설정] → ERP 토큰 에 넣습니다.
  * 값을 바꾸려면: [새 버전 수정 및 배포] → [변수 및 보안 비밀] → 수정 → 배포


■ 그 외 비밀값 (DB 접속, JWT, 알림톡 키 등) — Secret Manager에 있습니다

  https://console.cloud.google.com/security/secret-manager?project=tossplugincar-dev

  시크릿 클릭 → [버전] 탭 → latest 행 오른쪽 ⋮ → [보안 비밀 값 보기]

  DATABASE_URL             DB 접속 문자열 (사용자/비밀번호 포함)
  JWT_SECRET               관리자 로그인 토큰 서명키
  ADMIN_BOOTSTRAP_EMAIL    최초 관리자 계정 이메일
  ADMIN_BOOTSTRAP_PASSWORD 최초 관리자 계정 비밀번호 (※ 아래 주의 참고)
  PROMOTION_JOB_TOKEN      배치 잡 인증
  TOSS_WEBHOOK_SECRET      토스 웹훅 서명 검증
  SOLAPI_API_KEY / SECRET / SENDER   알림톡 발송

  ※ ADMIN_BOOTSTRAP_PASSWORD 주의
    이 값은 "관리자가 하나도 없을 때 처음 만들 값"입니다. 이미 계정이 있으면
    시크릿을 바꾸고 재배포해도 DB의 비밀번호는 바뀌지 않습니다.
    → 비밀번호를 바꾸려면 관리자 웹 [내 비밀번호 변경]을 쓰세요.


■ POS 토큰 (X-Store-Token) — 매장 탭앱이 쓰는 값. 매장마다 다릅니다

  관리자 웹 → [매장 개통 설정] → 해당 매장 행 → POS 토큰 [보기] / [복사]

■ 서버 — main 브랜치에 push하면 Cloud Build가 자동 배포합니다 (2~4분)

    git push origin main

  * DB 마이그레이션은 컨테이너 부팅 시 자동 실행됩니다(RUN_MIGRATIONS_ON_BOOT=true).
  * 배포 전 Cloud SQL이 켜져 있는지 확인하세요. 꺼져 있으면 모든 리비전이
    부팅에 실패해 크래시 루프에 빠집니다.
  * 반영 확인:  curl https://chevrolet-api-813801981857.asia-northeast3.run.app/health/ready
                → {"ok":true} 면 정상

■ POS 탭앱 — ZIP을 만들어 토스 개발자센터에 업로드합니다

    $env:CHEVROLET_API_BASE_URL = 'https://chevrolet-api-813801981857.asia-northeast3.run.app'
    .\pos-plugin\package.ps1

  → pos-plugin\chevrolet-pos-plugin-foldered.zip 을 업로드
     (-foldered 가 붙은 쪽입니다. dist/ 폴더로 감싼 구조라야 개발자센터가 받습니다)

  * 환경변수를 빠뜨리면 빌드가 멈춥니다(일부러 그렇게 해뒀습니다). 주소가 빠진
    번들은 단말기에서 "네트워크 연결을 확인하세요"만 뜨고 원인을 못 찾습니다.

■ 전산 시뮬레이터(PyQt) — 단독 exe

    cd erp-simulator
    .\build.ps1

  → dist\쉐보레정비전산.exe (약 33MB, 파이썬 없는 PC에서도 실행)

  * exe를 남에게 줄 때는 exe 파일만 주세요. 같은 폴더의 config.ini에는
    ERP 토큰이 들어 있습니다.

  1) 관리자 웹 → [가맹점 관리 — 매장 등록]
       merchantId(토스 가맹점 번호), 매장명, 사업자번호 입력

  3) 매장 POS → 정비 대기열 탭앱 → POS 토큰 입력

  * 전산 코드가 없으면 그 매장으로는 전산 주문이 들어오지 못합니다(404).
  * 전산이 사업자번호를 함께 보내면 첫 주문에서 코드가 자동으로 연결됩니다.

■ "전산에서 보냈는데 POS에 안 떠요"

  관리자 웹 → [전산 주문 이력] → 상태 확인

    pending    서버까지는 왔음. POS가 아직 안 가져감
               → 매장 POS 탭앱이 켜져 있는지, 토큰이 맞는지 확인
    loaded     POS 장바구니에 담김 (정상)
    paid       결제까지 완료 (정상, 최종)
    failed     POS가 담다가 실패 — 사유가 함께 표시됩니다
    dismissed  매장 직원이 화면에서 지웠음
    expired    24시간 동안 아무도 처리하지 않아 만료됨
    cancelled  전산에서 취소함

  목록에 아예 없으면 → 전산이 우리 서버까지 오지 못한 것입니다.
    전산 쪽 로그, ERP 토큰, 전산 코드(storeCode)를 확인하세요.

■ "POS 화면이 가끔 멈춰요"

  탭앱은 5~15초 간격으로 서버를 확인합니다(한산하면 느려지고, 변화가 생기거나
  직원이 뭔가 누르면 바로 빨라집니다). 15초 이상 멈춰 있으면 네트워크나 토큰
  문제입니다. 우상단 연결 표시등 색을 보세요.

■ "관리자 웹 비밀번호를 잊었어요"

  재설정 메일 기능이 없습니다. 복구는 DB를 직접 고치는 수밖에 없습니다.

    1) 로컬에서:  node backend/scripts/hash-password.js
                  (새 비밀번호를 입력하면 실행할 SQL이 통째로 출력됩니다)
    2) Cloud SQL Studio에서 그 SQL 실행

  ※ 잊기 전에 관리자 웹 [내 비밀번호 변경]으로 바꿔두세요.

■ 배포가 안 돼요

  Cloud Build 목록에서 맨 위 빌드 상태를 보세요.
    실패     → 로그의 마지막 에러 줄 확인
    빌드 없음 → 트리거가 안 걸린 것. 저장소 연결을 확인하세요.


┌──────────────────────────────────────────────────────────────────────────────┐
│ 6. 로컬 개발                                                                 │
└──────────────────────────────────────────────────────────────────────────────┘

  테스트 (로컬 Postgres 필요. 운영 DB로는 절대 돌리지 마세요)

    $env:DATABASE_URL = 'postgresql://postgres:devpass@localhost:5432/devdb?schema=public'
    cd backend
    npm test

  * 현재 140개 통과.
  * --test-concurrency=1 을 지우지 마세요. 테스트 파일들이 같은 DB를 비우기 때문에
    병렬로 돌리면 서로의 데이터를 지웁니다.

  서버 로컬 실행

    cd backend
    npm start        (기본 8080 포트, PORT 환경변수로 변경 가능)

  탭앱 미리보기

    cd pos-plugin
    npm run dev      (watch 모드. localhost에서는 같은 origin을 씁니다)

  □ DB 비밀번호 교체 (급함)
      2026-08-26 대화 중 노출됐습니다. 순서를 지켜야 합니다:
        1. Cloud SQL → 사용자 → chevrolet_app 비밀번호 변경
        2. Secret Manager → DATABASE_URL 새 버전 저장
        3. Cloud Run 재배포
      (시크릿을 먼저 바꾸면 그 사이 서버가 옛 비밀번호로 붙으려다 죽습니다)

  □ 결제 완료를 전산에 실시간 통보(푸시) — 미구현
      지금은 전산이 조회 API로 확인합니다(status: paid).
      실시간이 꼭 필요한지 먼저 정하는 게 좋습니다 — 재시도·중복 수신 처리를
      양쪽 다 만들어야 합니다.

  □ Cloud Scheduler 잡 2개 등록
      /internal/jobs/send-promotions  (프로모션 발송)
      /internal/jobs/purge-expired    (개인정보 파기 + 오래된 전산 주문 만료)
      헤더에 x-promotion-job-token 필요.

  □ 법무 검토 — 개인정보 수집·이용 동의 문구, 광고 수신거부 문구,
      보관기간(1095일), 알림톡 광고 템플릿

  ※ 토스 SDK 문서와 실제가 다른 부분이 있습니다.
     pos-plugin/src/lineItem.js 상단 주석에 실측으로 확인한 9가지를 적어뒀습니다.
     특히 key는 "자동 생성됨"이라고 문서에 적혀 있지만 실제로는 생성되지 않습니다.
